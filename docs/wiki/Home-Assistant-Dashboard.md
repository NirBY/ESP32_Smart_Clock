# Home Assistant Dashboard

## What ESPHome Can And Cannot Control

ESPHome can organize Home Assistant by assigning entities to logical sub-devices
and by marking settings as configuration entities.

ESPHome cannot add custom explanatory text under each control in Home Assistant's
stock device page. That page is generated by Home Assistant. The best place for
friendly explanations is a dashboard card.

## Logical Devices

The firmware exposes these logical Home Assistant devices:

| Device | Purpose |
| --- | --- |
| ESP32 Smart Clock Display | Matrix brightness, time format, manual message text, and display timing controls. |
| ESP32 Smart Clock Alarm | Alarm enable, hour, minute, and alarm message duration. |
| ESP32 Smart Clock Audio | Speaker playback, speaker wiring hint, hourly beep, quiet hours, and media label duration. |
| ESP32 Smart Clock System | Startup, Wi-Fi, network, sensor, speaker, power alert controls, and GitHub release firmware updates. |
| ESP32 Smart Clock Sensors | AHT20 and BMP280 readings. |

Most settings are also marked as Home Assistant `config` entities. That keeps
the normal device page cleaner while still leaving real controls and readings
easy to find.

## Dashboard Template

The Display device includes **Display Rotate 180**, a configuration switch for
a matrix mounted upside down. It rotates all four modules as one screen, applies
immediately, and remembers the setting after a restart. Leave it off for normal
mounting. It is also included in the dashboard template. For a second clock,
use the entity ID assigned by Home Assistant for that clock.

Use `docs/home-assistant-dashboard.yaml` as a ready-to-paste Home Assistant
dashboard view. It uses built-in Home Assistant cards plus the included brightness range editor:

- Markdown cards for the explanations Home Assistant cannot show below controls
  on the generated device page.
- Entity cards for quick glance controls.
- Entities cards grouped by Display, Alarm, Audio, System Alerts, Firmware Checks, and Sensors.

If Home Assistant generated different entity IDs on your system, edit the YAML
entity IDs after pasting it into the dashboard editor.

## Add It In Home Assistant

1. Open Home Assistant.
2. Go to Settings > Dashboards.
3. Create a new dashboard or open an existing dashboard.
4. Choose Edit dashboard.
5. Open the raw YAML editor.
6. Paste the contents of `docs/home-assistant-dashboard.yaml`.
7. Save.

For a single-card workflow, you can also go to the device page and use
Add to Dashboard, but Home Assistant chooses the generated card layout there.
The YAML template gives a cleaner, intentional control surface.

## Brightness Time Picker Card

1. Copy `docs/home-assistant/smart-clock-brightness-card.js` into your Home Assistant `/config/www/` directory (create `www` if necessary).
2. In Settings > Dashboards > Resources (enable Advanced mode in your profile if needed), add `/local/smart-clock-brightness-card.js?v=1` as a **JavaScript module**. Reload the browser.
3. Paste the updated dashboard YAML. For a single manual card use:

```yaml
type: custom:smart-clock-brightness-card
entity: text.esp32_smart_clock_brightness_schedule
```

The card shows a dynamic list of rows with **From** and **Until** time pickers, a brightness number (0–15), and **Remove**. **Add range** appends a row. **Save** applies the whole list; **Reload** discards unsaved edits. Removing all rows and saving clears the schedule. Turn on **Day / night automatic brightness** in Display to activate it. The card validates input and keeps edits when saving fails. It uses the existing firmware storage entity internally, so users do not type the serialized schedule. No HACS dependencies are required.

Native time picker appearance follows the browser and operating system. The clock supports up to 254 stored characters (17–18 ranges depending on brightness values). Cross-midnight ranges are supported; the last matching range wins. Outside all ranges, the manual brightness applies.
