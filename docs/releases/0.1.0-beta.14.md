# ESP32 Smart Clock 0.1.0-beta.14

Updated the clock to ESPHome 2026.9.0 and documented phone-based Wi-Fi recovery
through **ESP32 Smart Clock Fallback**, including a screenshot of the original
portal rendered with example network data. The recovery timeout is explicitly
90 seconds.

## Software

- ESPHome 2026.9.0, native ESP-IDF 5.5.5 toolchain.
- pioarduino 55.03.312 / Arduino-ESP32 3.3.12 for the two Arduino variants.
- ESP32-A2DP 1.8.11; pinned current AHTX0 2.0.6, BMP280 3.0.0,
  GFX 1.12.6 and MD_MAX72XX 3.5.1.
- Separate PlatformIO environments: 6.1.19 for ESPHome's dependency and 6.2.0
  for Arduino builds. CI uses the same separation and the tracked ESPHome version.
- Replaced the reserved all-zero public example API key with a valid nonzero
  example key; personal builds must use a unique private key.
- CI collects firmware from both native ESP-IDF and legacy PlatformIO build paths.
- Windows documentation and editor paths migrated to C:\workspace\esp32_smart_clock.

## Validation

- ESPHome configuration validated and firmware compiled successfully.
- Hardware-test and Bluetooth-speaker firmware compiled successfully.
- ESPHome beta.14 flashed over USB to ESP32-D0WD-V3 revision 3.1; written data verified.
- Tested recovery with a deliberately nonexistent SSID: fallback AP started,
  the real portal and configuration endpoint returned HTTP 200, and saving
  correct Wi-Fi credentials restored the connection.
- Saved credentials survived a device restart.
- Final firmware rebuilt with the correct private local settings, flashed,
  and authenticated over the encrypted ESPHome API; 29 entities were enumerated.

## Known hardware limitation during validation

The attached unit still reports AHT20 and BMP280 communication failures, as it
already did before this upgrade. Sensor readings are not verified. Audio quality
and Bluetooth playback were not tested on the physical unit in this release.

## Updating

Build and install from your local YAML and private secrets for normal use.
Public release binaries are built in CI from `secrets.example.yaml`, with
placeholder Wi-Fi credentials and an example API key; they do not contain the
owner's private credentials. The fallback hotspot password in public builds is
`CHANGE_ME_FALLBACK_AP_PASSWORD`. Set up Wi-Fi through the portal, and configure
Home Assistant with the matching API key, or install your personalized build.

See [the README recovery guide](../../README.md#recover-wi-fi-from-your-phone).
